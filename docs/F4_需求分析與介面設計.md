F4 活動與教室配置
一、需求分析
1. 功能目的
F4 負責校園活動的時段管理與教室配置，讓使用者能新增及查詢活動、安排活動時間、配置適合的教室，並檢查活動時段與教室使用是否衝突。
本模組需配合共用專案的 `model.py` 及其他功能模組，使用共用資料，避免重複建立獨立的資料結構。

2. 功能需求
（1）活動管理
- 新增活動名稱、活動時段及預計參加人數等資料。
- 查詢活動的名稱、時間及教室。
- 依專案需求提供活動資料修改功能。

（2）活動時段管理
- 設定活動的星期與開始、結束節次。
- 檢查活動是否與其他活動的時段重疊。
- 檢查活動是否與既有課程衝堂。
- 提供活動時段資料，供 F3 個人課表與空堂查詢使用。

（3）教室配置
- 根據活動參加人數選擇適合的教室。
- 檢查教室容量是否足夠。
- 檢查教室是否已被課程或其他活動使用。
- 若配置失敗，顯示原因並讓使用者重新選擇。

（4）資料驗證
- 檢查活動資料是否完整。
- 檢查星期、節次、人數及教室代碼是否有效。
- 發生衝突或資料錯誤時，顯示清楚的提示。
- 避免將未通過檢查的資料加入共用資料。

3. 系統限制
- 活動時段須符合專案規定的星期及節次格式。
- 同一教室不能在相同時段安排不同課程或活動。
- 教室容量須大於或等於活動預計參加人數。
- 活動與課程衝堂時，應依專案規定處理，不得直接忽略衝突。
- 活動及教室資料須與共用模組保持一致。

二、介面設計

1. 主選單
F4 預計提供以下操作：
1. 新增活動
2. 查詢活動
3. 修改活動
4. 配置活動教室
5. 查詢教室使用情況
0. 返回主選單

 2. 新增活動介面
使用者輸入活動名稱、活動星期、開始節次、結束節次及預計參加人數。系統驗證資料後，才儲存活動。

 3. 教室配置介面
使用者選擇活動後，系統檢查符合容量及時段條件的教室。若找到合適教室，顯示配置結果；若沒有，顯示原因並請使用者重新選擇。

 4. 活動查詢介面
使用者可依活動代碼、名稱或星期查詢，並查看活動時段、參加人數及配置教室。

 5. 錯誤提示
- 活動時段格式錯誤，請重新輸入。
- 此時段已有其他活動，無法安排。
- 此教室已被課程占用，請選擇其他教室。
- 教室容量不足，請選擇其他教室。
- 找不到指定的活動或教室。

三、介面設計原則
1. 操作簡單，提供清楚的輸入提示。
2. 使用共用專案資料，避免資料重複。
3. 衝突發生時，提供明確的錯誤訊息。
4. 活動資料需能與 F3 課表及空堂查詢整合。

四、預期成果
完成 F4 後，使用者可以管理活動時段、配置合適教室，並檢查活動與課程的時間衝突及教室容量限制，讓活動資料能與其他模組共同使用。
